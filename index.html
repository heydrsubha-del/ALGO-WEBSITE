01 / The platform

One message.
Multiple lines of evidence.

Instead of relying on a single suspicious word or score, the workflow brings distinct signals together and keeps the reasoning visible.

01⌕

Explainable detection

A text classifier, header checks, identity anomalies, link signals, and origin context contribute to a weighted risk view you can inspect.

Signal contribution · illustrative
02⌖

Trace the route

Reconstruct mail hops and review approximate origin and infrastructure clues, including VPN or Tor context.

03⌘

Connect related cases

Compare indicators and origin patterns to surface possible campaigns. Optional local models can add evidence-limited narratives and semantic comparisons.

Local models are optional ↗
04▤

Keep the evidence clear

Prepare reports with the score breakdown, extracted indicators, routing observations, and a hash of the source evidence.

Markdown report exports ↗

03 / Privacy & control

Designed to keep
analysis deliberate.

The project is local-first. Email analysis and optional integrations run in the environment hosting the application. This informational site does not accept email uploads or run an analysis.

Read the project privacy notes ↗
⌂

Local-first by default

The app’s default workflow stores threat memory locally. Optional network services are described in the project documentation.

◉

Mailbox access stays read-only

The documented IMAP connection does not mark, move, or delete messages.

⟡

People stay in the loop

Scores and correlations are investigative leads. A reviewer should assess the evidence and limitations.
